# GeeLo · 送进编辑器 · 设计与复现

**一句话**：右键任意本地 `.js` →「以 GEE 打开」→ 你平常那个已登录的 Chrome 弹出
Code Editor，**代码已经在编辑器里**。

> 建立于 2026-08-18。本文件记录**为什么这么做**、**怎么做的**、**踩了什么坑**，
> 目的是换台电脑、或者交给别人时能原样复现。

---

## 🡒 刚把这个文件夹拷到新电脑？直接跳到 **第八节**

那一节是一份从零开始的完整清单（装什么、怎么授权、怎么选仓库、怎么验），
每一步都实测过，**照着做就行，不用读前面**。

会卡住的只有一处：**必须先有一个已存在的脚本仓库**——
EE 不支持 push 时自动创建，而且并没有官方文档说的 `users/<你>/default`。
详见 8.4。

## 日常怎么用（设置完之后）

**右键任意 `.js` → 「以 GEE 打开」**。约 2 秒后 Chrome 弹出 Code Editor，代码已在编辑器里。
（Windows 11 可能要先点「显示更多选项」。）

三条规则：

1. **脚本名 = 文件名去掉 `.js`**，落在你选定的那个仓库下
2. **本地文件是唯一源头**，同名脚本会被覆盖；但**仓库里其他脚本绝对安全**
   （推送前会先 `fetch` 对齐服务端，只覆盖当前这一个）
3. **内容没变就不推送**，只重新打开页面

# 一、目标与硬约束

目标很简单：省掉「打开浏览器 → 找到 Code Editor → 新建脚本 → 切回编辑器 → 全选复制 → 粘贴」
这一串动作。

但有三条硬约束，是它们决定了最后选哪条路：

| 约束 | 为什么 |
|---|---|
| **必须用现有的、已登录的 Chrome** | 不能要求每次或每台机器重新登录 Google |
| **不许碰账号凭据** | 不复制 cookie、不搬 profile、不存密码 |
| **不能依赖网页内部结构** | Google 一改版就失效的方案不算数 |

# 二、四条路，为什么选第 1 条

## ✅ 方案 1（采用）：EE 脚本仓库 + `?scriptPath=` 官方参数

Earth Engine 的脚本仓库**本身就是 git 仓库**，托管在 `earthengine.googlesource.com`。
而 Code Editor 支持一个官方 URL 参数：

```
https://code.earthengine.google.com/?scriptPath=<仓库>:<脚本名>
```

于是「把本地文件送进编辑器」被拆成两个都很稳的动作：

```
git push  →  开一个 URL
```

- 用的是你平常的 Chrome（不传 `--user-data-dir`，就是默认 profile），登录态原样在
- 不接触任何账号凭据
- 官方 URL 参数，与页面 DOM 无关，改版不受影响
- **额外好处**：脚本自动进 Scripts 面板，还能用 `?accept_repo=` 一键分享给别人

代价：一次性要生成一个 googlesource 专用的 git 密码（约 2 分钟，做一次）。

## ❌ 方案 2（试过，撤回）：复制 Chrome profile + CDP 注入

思路是：把登录态复制到一个独立 profile，用 `--remote-debugging-port` 开 CDP，
再用 `Input.insertText` 把代码打进编辑器。

**撤回原因（两条，任何一条都足够否掉它）**：

1. **它要搬你的登录 cookie**，等于在本机复制账号凭据。既有被 Google 判为异常登录
   的风险，也不该由一个小工具来做。
2. 实测**根本做不成**：`User Data\Default\Network\Cookies` 被正在运行的 Chrome
   独占锁定，`Copy-Item` 直接报 `being used by another process`。

顺带记一条实测结论：**Chrome 136+ 禁止对默认 profile 开 `--remote-debugging-port`**，
所以「直接在你现有 Chrome 上开调试端口」这条路从一开始就不通。

## ❌ 方案 3：Chrome 扩展

装一个本地扩展，content script 从 `127.0.0.1` 的小服务取代码填进编辑器。
不碰账号，也能全自动。否掉的原因：

- Chrome 每次启动都弹「请停用以开发者模式运行的扩展程序」
- 注入依赖 GEE 页面内部结构，违反第三条硬约束

## ❌ 方案 4：剪贴板 + 手动 Ctrl+V

零设置、零风险、永不失效，但要手动按两下键，不满足「代码也在里面」。
**留作应急**：任何时候方案 1 出问题，复制粘贴永远可用。

# 三、目录里有什么

> **这是 GeeLo 的功能二，装在 `GeeLo\送进编辑器\`，而且是可选的。**
> 它是**配一次就再也不用管**的那个——设置完之后你只会用到右键那一下。
> （功能一 `测试台\` 相反：AI 每写一版脚本就跑一次，那才是核心。）

```
送进编辑器\
├ 说明.md              你在看的这份
├ gee-open.js          主程序（Node，零依赖）
├ 配置.json            设置后自动生成，记着用哪个仓库
├ 设置.bat          ★ 一次性设置：查 git → 查凭据 → 发现仓库 → 克隆
├ 注册右键菜单.bat   ★ 往右键菜单加「以 GEE 打开」
├ 取消右键菜单.bat     撤销上一条
├ 以GEE打开.bat        右键菜单实际调用的就是它（也可直接把 .js 拖到它上面）
├ 看看配置.bat         看当前用的哪个仓库、凭据在不在、代理走哪
└ 示例\
   └ 测试_能不能通.js  ★ 新电脑上先右键这个，验证整条链路
```

★ **`配置.json` 是本机专属的**（记着用哪个仓库、克隆在哪）。
换电脑时**要么删掉它、要么无视**——工具会检查它是不是属于当前账号，
不属于就明确报错，不会闷声推到别人的仓库里去。

本地克隆**不在这个文件夹里**，在 `%LOCALAPPDATA%\GeeLo\repo\`，
免得把仓库内容混进项目目录。

**零依赖**：只用 Node 自带的模块 + 系统自带的 `git`、`curl.exe`、`reg.exe`。
不需要 `npm install`。

# 四、一次性设置（做一次，之后永远不用管）

> **换电脑/换账号请直接看第八节**，那份清单更完整（含全新账号的情况）。
> 本节只讲原理层面的三件事：前提、步骤、代理。

## 4.1 前提

| 需要 | 怎么确认 | 没有怎么办 |
|---|---|---|
| Node.js | `node -v` | 已经有了（跑 GEE 测试台就在用） |
| git | `git --version` | https://git-scm.com/download/win |
| curl.exe | `curl --version` | Windows 10 1803+ 自带 |
| 能访问 Google | 见下 | 见 4.3 |

## 4.2 三步

```
1. 双击《设置.bat》
     └─ 第一次会停在「缺 git 凭据」，并自动用 Chrome 打开授权页
2. 授权页上点 Generate Password → 选 Windows 标签页 → 整段复制
   → 粘进 cmd 回车（写出 %USERPROFILE%\.gitcookies）
   → 再双击一次《设置.bat》
     └─ 这次会停在「你名下有多个仓库」，并把它们列出来
3. 挑一个仓库，命令行跑：
     node gee-open.js --setup --repo=users/你的用户名/仓库名
4. 双击《注册右键菜单.bat》
```

★ **第 3 步为什么躲不掉**：EE **不支持 push 时自动建仓库**（实测直接报
`fatal: repository ... not found`），所以必须指定一个**已经存在**的仓库。
建议在 Code Editor 里新建一个专用的（Scripts 面板 → NEW → Repository），
别把自动推送混进正在用的工作仓库。

选定的仓库记录在同目录 `配置.json` 里（`配置.json` 是**本机专属**的，不进版本库）。
想换仓库，重跑一次第 3 步即可。

★ 想看自己当前用的是哪个：双击《看看配置.bat》。

★ **关于那个密码**：它是 googlesource 专用的 git 凭据，
**不是**你的 Google 账号密码，可以随时在同一个页面吊销。
本工具不读、不存、不传你的任何账号信息——它只是让 `git` 能认证。

## 4.3 代理

工具**不自己探测代理**，而是复用两个已有来源，优先级：

```
git config --global http.proxy   →   环境变量 HTTPS_PROXY / HTTP_PROXY
```

所以如果你的 `git` 本来就配好了代理，这里什么都不用设。
若 `git` 连不上 Google，先把这一条配好：

```bat
git config --global http.proxy http://127.0.0.1:你的端口
```

实测验证办法（不需要认证，能返回一行 ref 就说明代理通了）：

```bat
git ls-remote --heads https://gerrit.googlesource.com/gcompute-tools
```

# 五、每次使用时，内部发生了什么

```
右键 xxx.js →「以 GEE 打开」
   │
   ├─ Explorer 读注册表 HKCU\...\SystemFileAssociations\.js\shell\OpenWithGEE\command
   │    值 = "…\以GEE打开.bat" "%1"
   │
   ├─ 以GEE打开.bat  →  node gee-open.js "<文件路径>"
   │
   ├─ ① git fetch origin  +  git reset --hard origin/master
   │      把本地克隆对齐到服务端。
   │      ★ 为什么要 reset：你可能在 Code Editor 里改过**别的**脚本，
   │        先接受服务端版本，再覆盖当前这一个，就永远不会有合并冲突。
   │        语义是「本地文件是这个脚本的唯一源头，别的脚本以服务端为准」。
   │
   ├─ ② 把文件写进克隆目录，**去掉 .js 扩展名**
   │      （EE 仓库里的脚本名不带扩展名，带了在 Scripts 面板里很难看）
   │
   ├─ ③ 内容有变才 commit + push origin HEAD:master
   │      （没变就跳过，省两秒）
   │
   └─ ④ 启动 chrome.exe（**不带 --user-data-dir**，所以用的是你平常的 profile）
          打开 https://code.earthengine.google.com/?scriptPath=<仓库>:<脚本名>
```

脚本名含中文时用 `encodeURIComponent` 编码，仓库路径里的 `/` 和分隔用的 `:` 保持原样
（官方文档的例子就是不编码的：`?scriptPath=users/username/utils:utils`）。

# 五之二、怎么验证它真的成了（2026-08-18 实测记录）

★ **不要只看工具自己打印的「已推送」**——那只说明 git 没报错。
要去服务端独立核对。下面这套办法可以原样重跑：

```powershell
$r = "$env:LOCALAPPDATA\GeeLo\repo"

# ① 重新 fetch，只看服务端的 ref，不看本地
git -C $r fetch origin -q
git -C $r log --oneline -1 origin/master

# ② 文件总数：推之前几个，推之后应该正好多 1
(git -C $r ls-tree --name-only origin/master).Count

# ③ 抽查几个原有脚本还在不在（确认没被 reset --hard 冲掉）
git -C $r ls-tree --name-only origin/master | Select-String "你原有的某个脚本名"

# ④ ★ 最硬的一条：比对 blob 哈希
#    两边一致 = 服务端内容与本地文件逐字节相同
git -C $r rev-parse "origin/master:脚本名"
git hash-object "本地\路径\脚本名.js"
```

开发时实测的结果长这样（供对照）：

| 检查项 | 结果 |
|---|---|
| 提交落地 | `更新 RSEI_哨兵2_厦门岛` 这一条真出现在 `origin/master` 上 |
| 文件数 | **只增 1，不减**（推之前 N 个，推之后 N+1 个） |
| 原有脚本抽查 5 个 | 全在（确认 `reset --hard` 没冲掉别的脚本） |
| **blob 哈希** | 服务端 = 本地，逐字节相同 |

**中文脚本名**这一关单独验过（这是最容易出问题的地方）：
拿生成的那段百分号编码直接去请求 Google 的 gitiles，

```powershell
# 把 <你的仓库> 换成 users/你的用户名/仓库名
curl.exe -b "$env:USERPROFILE\.gitcookies" `
  "https://earthengine.googlesource.com/<你的仓库>/+/master/RSEI_%E5%93%A8%E5%85%B52_%E5%8E%A6%E9%97%A8%E5%B2%9B?format=TEXT"
```

返回 **HTTP 200**，base64 解出来正是那份脚本、首行 `/**`——
说明 `encodeURIComponent` 产生的编码在 Google 侧能正确还原。

# 六、实现时踩的坑

## 坑 1　.bat 里出现中文文件名 → 换个代码页就崩

**现象**：

```
Error: Cannot find module 'C:\...\送进编辑器\??GEE.js'
```

主程序原本叫 `开GEE.js`，`.bat` 里写着 `node "%~dp0开GEE.js"`。
从 Explorer 双击（代码页 936）正常，从 UTF-8 控制台调用就找不到文件。

**原因**：cmd 按**当前控制台代码页**解析 .bat 的字节。同一份 GBK 字节，
在 936 下解出「开」，在 65001 下就是乱码。

**解法**：**把 .bat 里所有功能性引用改成纯 ASCII**——主程序改名 `gee-open.js`。
这样 .bat 的字节在任何代码页下都一样，整类问题消失。
（文件夹名可以是中文，因为 `%~dp0` 是 cmd 运行时从真实路径展开的，不来自 .bat 的字节。）

## 坑 2　Node 输出 UTF-8，Explorer 的控制台是 cp936 → 中文提示全乱码

**现象**：右键弹出的黑窗口里，所有中文报错都是 `�����`。

**原因**：Node 往 stdout 写 UTF-8；Explorer 起的 cmd 默认代码页是 936。

**解法**：`.bat` 开头加 `chcp 65001 >nul`。

★ 注意这和《说明.md》（测试台那份）的**坑 7 不矛盾**：那里说「加 chcp 也救不回来」，
指的是 **.bat 自身含中文**的情况——chcp 那一行生效前，后面几行已经被按旧代码页解过了。
本项目的 .bat 是**纯 ASCII**，不存在自身被解错的问题，所以 chcp 完全有效。
**两个坑的正确组合是：.bat 全 ASCII + chcp 65001 + 所有中文交给 Node 输出。**

核对办法（高位字节必须是 0）：

```powershell
Get-ChildItem *.bat | ForEach-Object {
  $b = [System.IO.File]::ReadAllBytes($_.FullName)
  "{0} 高位字节 {1}" -f $_.Name, ($b | Where-Object { $_ -gt 127 }).Count
}
```

## 坑 3　注册表值里全是引号，写在 .bat 里转义会疯

`command` 的值必须是 `"C:\...\以GEE打开.bat" "%1"`，在 .bat 里用 `reg add /d`
要写成 `"\"%BAT%\" \"%%1\""`，可读性极差且容易错。

**解法**：注册表操作交给 Node 的 `spawnSync('reg', [...])` 做——参数是数组，
不经过 shell，一个转义都不用写。`.bat` 只负责调 `node gee-open.js --register`。

## 坑 4　Gitiles 的 JSON 前面有一行防 XSSI 前缀

`https://earthengine.googlesource.com/?format=JSON` 返回的正文以 `)]}'` 开头，
直接 `JSON.parse` 会炸。要先 `body.replace(/^\)\]\}'\s*/, '')`。

## 坑 5　Node 的 fetch 不读代理环境变量

Node 22/24 虽然自带 `fetch`，但它**不认** `HTTPS_PROXY`。
所以「问服务器有哪些仓库」这一步不用 `fetch`，改用 `curl.exe --proxy ... -b ~/.gitcookies`
——顺带还解决了「怎么带上 Netscape 格式的 cookie 文件」。

## 坑 6　`/?format=JSON` 返回的是**全服务器**的仓库，不是你的

**现象**：设置时打印「可访问仓库 **35900** 个」，然后让你从三万多条里挑一个。

**原因**：`https://earthengine.googlesource.com/?format=JSON` 列的是**所有你有权
看到的**仓库——EE 的脚本仓库默认对所有 EE 用户可读，所以基本等于全站。

**解法**：从 `.gitcookies` 里解出用户名再过滤。cookie 名字形如
`git-<你的用户名>.gmail.com=…`，中间那段就是 EE 用户名。
按 `users/<用户名>/` 前缀一过滤，就只剩你自己名下那几十个，清清爽爽。

★ 顺带一个反直觉的实测：**没有 `users/<你>/default` 这个仓库**。
官方文档说「你的私有脚本存在 `users/username/default`」，但实测账号上它并不存在
（`git ls-remote` 报 not found）。所以代码里不能把 `default` 写死。

## 坑 7　`spawnSync` 默认缓冲区装不下仓库列表

**现象**：

```
✗ 拿不到仓库列表：curl 执行失败：spawnSync curl.exe ENOBUFS
```

**原因**：三万多个仓库的 JSON 有好几 MB，超过了 `spawnSync` 的默认 `maxBuffer`。

**解法**：`maxBuffer: 64 * 1024 * 1024`。

★ 更值得记的是**第二个错误**：我当时把这个失败也归到「凭据过期，删掉重来」，
差点让人白白重新生成一次凭据。**「命令没跑起来」和「服务器拒绝了」必须分开报**
——前者看 `spawnSync` 的 error，后者看 HTTP 状态码。代码里现在是两条不同的分支。

## 坑 8　`配置.json` 带 BOM → 报成「还没设置过」

**现象**：配置明明在，工具却说「还没设置过。先双击《设置.bat》」。

**原因**：`JSON.parse` 见到 UTF-8 BOM 直接抛异常，而我把「解析失败」和
「文件不存在」都归成了 `return null`，于是报出一句完全误导的提示。
用**记事本**或 PowerShell 的 `Set-Content -Encoding UTF8` 存过这个文件就会带 BOM。

**解法**：读进来先 `raw.replace(/^﻿/, '')`；
并且**解析失败要单独报错**（"配置.json 读不动"），不要和"没有配置"混为一谈。

★ 这是个通用教训：**「东西不存在」和「东西存在但坏了」必须报不同的话**，
否则排查方向会整个跑偏。本项目里同样的错犯过两次（另一次是坑 7 的
"curl 没跑起来" vs "服务器拒绝"）。

## 坑 9　换仓库时只改 remote，会留着上一个仓库的历史

**现象**：换到另一个仓库后，本地克隆里还是上一个仓库的文件。

**原因**：原来的代码在克隆已存在时只做 `git remote set-url`，没换内容。

**解法**：设置时比对 `git config --get remote.origin.url` 与目标 URL，
**不一致就整个删掉重新克隆**。换账号时尤其要紧。

## 坑 10　全新账号名下 0 个仓库，会掉进「让你从空列表里挑一个」

**现象**：新账号跑设置，提示「你名下有多个仓库」，底下却什么都没有。

**原因**：只写了 `=== 1` 和 `else` 两个分支，忘了 `=== 0`。

**解法**：`length === 0` 单独一个分支，直接告诉他去 Code Editor 建仓库，
并自动帮他把 Code Editor 打开。

## 坑 11　`core.autocrlf=true` 让「内容变没变」判断失效

**现象**：明明该跳过推送，却报

```
✗ 提交失败：nothing to commit, working tree clean
```

**原因**：Windows 上 `core.autocrlf` 默认常是 `true`。
克隆时 git 把 LF 转成 CRLF 写进工作区 → `git status --porcelain` 报「有改动」；
但 `git add` 又把 CRLF 转回 LF → 实际什么都没暂存 → `git commit` 报 nothing to commit。

**解法**：**不能用 `git status` 判断**，要**先 add 再看暂存区**：

```js
git(['add', '-A'], repoDir);
const staged = git(['diff', '--cached', '--quiet'], repoDir);  // 0=无变化 1=有变化
if (staged.code === 1) { /* commit + push */ }
```

★ 顺带一提：**不要**为了绕开它去改 `core.autocrlf`。
已经用 `autocrlf=true` 检出过的克隆，一旦改成 `false`，
git 会认为**每一个文件**都变了（CRLF vs LF），`git add -A` 会造出一个
把全仓库行尾都改一遍的巨型提交。修判断逻辑才是对的。

## 坑 12　新机器上 git 没配身份，commit 直接失败

`git commit` 在没有 `user.email` 的机器上会报错退出。
解法：`gee-open.js` 先查 `git config --global --get user.email`，
查不到才用 `-c user.name=... -c user.email=...` 临时兜底，
**不改动你的全局配置**。

## 7.2 `--no-browser`：只推送，不弹浏览器

```bat
node gee-open.js "<脚本.js>" --no-browser
```

**给 AI 迭代用的。** AI 写一版推一版，要是每次都弹一个 Chrome 标签页，

规矩写在 GeeLo 根目录的 `AGENTS.md` 铁律第 8 条，以及 `new-workspace.js` 生成的

→ 粘进一个 cmd 窗口回车。它会写出 `%USERPROFILE%\.gitcookies`。

# 八之二、凭据维护：什么时候该吊销、怎么换

## 8.2.1 先搞清楚那个 token 是什么

`%USERPROFILE%\.gitcookies` 里那一行长这样（值已隐去）：

```
earthengine.googlesource.com→FALSE→/→TRUE→2147483647→o→git-你的名字.gmail.com=1//0f……
                                                                              ^^^^^^^^^^
```

`1//0f……` 那一段**不是密码，是一个 OAuth refresh token**，作用域是 `googlesource.com`。

**谁拿到它，谁就能以你的身份读写你所有 EE 脚本仓库**——不需要你的 Google 密码，
也不过二次验证。所以它和账号密码一样要当回事。

好消息是它的**权限边界很清楚**：只能碰脚本仓库。碰不到你的 Google 账号、
碰不到 EE 资产（`projects/<你的项目>/assets/…`）、也碰不到功能一
（测试台用的是另一套凭据 `%USERPROFILE%\.config\earthengine\credentials`）。

## 8.2.2 什么时候必须吊销

- 这一行**曾经出现在任何会被保存的地方**：聊天记录、截图、邮件、笔记、共享文档
- 电脑给别人用过 / 修过
- 定期轮换（半年一次不过分）

## 8.2.3 ★ 最要紧的一条：删本地文件 ≠ 吊销

```
删掉 %USERPROFILE%\.gitcookies   →  只是本机不能用了
在页面上点 Revoke cookies        →  才是真正让那个 token 作废
```

泄露之后**只删本地文件毫无意义**，token 在 Google 服务端照样有效。
**必须去页面上点 Revoke。**

## 8.2.4 完整换发流程（2026-08-18 实操走通，每一步都有坑）

```
① 删掉 %USERPROFILE%\.gitcookies                    ← 先删，理由见下方「为什么」
② 打开 https://earthengine.googlesource.com/new-password
③ 点 Revoke cookies
     └─ ★ 它只是个**跳转链接**，会把你带到 Google 账号的「关联的应用」页面。
        点它本身**什么都没撤销**。
④ 在「关联的应用」页里点进 *.googlesource.com → 删除全部关联
     └─ ★★ 这一步才是真正的撤销。
        ★★ 只能删这一个！旁边那几个千万别碰：
             Google Earth Engine Authenticator  ← 删了功能一直接废，
                                                   要重跑 earthengine authenticate
             Earth Engine Code Editor           ← 你网页版编辑器的访问权
             Gemini                             ← 无关
⑤ 撤销后再访问 googlesource 会报
     NOT_FOUND: Requested entity was not found / Repository is not found
     └─ ★ 这是**正常的**，说明撤销生效了（浏览器对该站的授权一并没了）。
        先访问一次根路径 https://earthengine.googlesource.com/ 恢复授权，
        看到一长串仓库列表就说明好了。
⑥ 回到 /new-password → 点 Generate Password → 展开 Windows Users
     └─ 上面那段是 cmd 用的（git config 开头，两行），复制它
        下面那段是 Git Bash 用的（eval 'set +o history' 开头），不要
     └─ ★ 这次别再点 Revoke，否则刚生成的又被一起作废
⑦ 粘进一个 cmd 窗口回车                              ← 见下方「粘到哪里」
⑧ 双击 送进编辑器\设置.bat 重跑一次
```

**为什么第 ③ 步不能省**：页面给的命令是 `>>`（**追加**），不是覆盖。
不先删，文件里就会出现**新旧两行同名 cookie**，git / curl 该用哪个是不确定的，
于是出现"时好时坏"的诡异认证失败。**这个文件永远只该有 1 行。**

**★ 第 ⑤ 步粘到哪里**：粘进 **cmd 窗口**，
**不要粘进 AI 对话框、不要贴进任何聊天工具**。
一旦贴进对话，它就进了会被保存的文本，等于刚换完又泄露一次——
（这个错本项目里犯过两次，所以专门写在这里。）

## 8.2.5 换完怎么验（三步，不回显内容）

```powershell
$f = "$env:USERPROFILE\.gitcookies"

# ① 格式：Netscape 格式要求正好 6 个制表符，且只能有 1 行
$b = [System.IO.File]::ReadAllBytes($f)
"制表符 " + (($b | Where-Object { $_ -eq 9 }).Count) + " 个（应为 6）"
"行数 "   + (@(Get-Content $f | Where-Object { $_.Trim() -ne "" }).Count) + "（应为 1）"

# ② 新凭据服务端认不认（200=有效，401=无效）
curl.exe -s -o NUL -w "%{http_code}`n" -b $f "https://earthengine.googlesource.com/?format=JSON"

# ③ 端到端：右键任意 .js →「以 GEE 打开」，能推能开就是好了
```

★ 全程**不要 `cat` / `Get-Content` 打印文件内容**——那等于又把 token 显示一次。
只看**长度、行数、制表符个数、HTTP 状态码**就够判断了。

## 8.2.5b 怎么确认旧 token 真的死了（而不是自我安慰）

把旧那行写进一个临时 cookie 文件去请求一次，**看状态码，三种情况互不相同**：

| 请求 | HTTP | 含义 |
|---|---|---|
| 带**有效**凭据 | **200** + 仓库列表 JSON | 能用 |
| **不带**凭据 | **401** + `PERMISSION_DENIED: The caller does not have permission` | 没带 |
| 带**已作废**凭据 | **400** + 一个 HTML 错误页 | **带了，但已作废** ← 要的就是这个 |

关键在于三者**长得不一样**，所以能区分"没带"和"带了但失效"。
只有看到第三种，才算真正确认撤销成功。验完**立刻删掉那个临时文件**。

## 8.2.6 吊销后会发生什么

| 受影响 | 不受影响 |
|---|---|
| 功能二（推送会报 401） | 功能一 本地测试台（用的是另一套凭据） |
| 其他机器上同一个 token | 你的 Google 账号 / 密码 |
| | EE 资产、Code Editor 里手动保存脚本 |
| | GitHub 备份（那是 Windows 凭据管理器，另一套） |

修复只要重跑一次 `设置.bat`。
