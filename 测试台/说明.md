# GeeLo 测试台 · 说明

**一句话**：把 GEE 的 **JavaScript 原样**在本机跑一遍，真连 Earth Engine 服务器，
不用再一个个粘进 Code Editor。

本文件一份说完：**是什么 · 怎么用 · 内部怎么跑的 · 换台电脑怎么装 · 踩过哪些坑**。

> **想知道"它凭什么能在本机跑 GEE"→ 看同目录的《原理.txt》。**
> 那一份专讲原理：算力在谁那边、惰性计算为什么是唯一杠杆、
> 网络那道墙卡在哪、以及为什么这件事以前一直没做成。
> 交给别人接手、或者换台电脑怎么都调不通时，先看它。

> ### 🡒 换了新电脑？直接双击 **`安装.bat`**
> 它会：查 Node 版本 → 装依赖 → 跑环境自检，**每一项失败都会告诉你怎么办**。
> 之后通常只需要改 **`配置.txt`** 里的项目 ID 一行。详见第四节。

# 一、先澄清：这是 JS，不是 Python

| | 跑的是什么 | 用在哪 |
|---|---|---|
| **测试台本体** | **JavaScript**（Node 执行） | ✅ 全部实际测试 |
| Python 版 GEE | Python | ⚠️ 只在最初建这套东西时**探过一次路**（验证凭据还能不能连），之后再没用过 |

**为什么必须是 JS**：Code Editor 里的脚本就是 JavaScript。若改用 Python 版测，
等于把每个脚本翻译一遍——**翻译过程本身就会引入或掩盖错误**，
测的就不是你最终要交付、要粘进 Code Editor 的那份代码了。

（`pip install earthengine-api` 只用来跑一次 `earthengine authenticate` 拿凭据，
之后跑测试完全不需要 Python。）

npm 上的 `@google/earthengine` **就是 Code Editor 里那套 JS API**（Google 官方发布），
所以脚本一个字都不用改。

**自己验证一下**（看代码即可，要跑请用 `node 跑GEE.js 示例\演示_这就是CodeEditor的JS.js`）：
`示例\演示_这就是CodeEditor的JS.js` 用的全是 `var`、`function`、
`.map(function(){})`、`print`、`Map.addLayer`、`Export`——这些在 Python 版里根本不存在。
它**可以原封不动粘进 code.earthengine.google.com**，结果一样。

# 二、怎么用

> ### ⚠ 一件最容易踩的事：**不要直接 `node 某个GEE脚本.js`**
>
> ```
> ✗ node 示例\演示_这就是CodeEditor的JS.js     → ReferenceError: ee is not defined
> ✓ node 跑GEE.js 示例\演示_这就是CodeEditor的JS.js
> ```
>
> 因为 GEE 脚本里的 `ee` / `print` / `Map` / `Export` 都是**运行环境提供的**，
> 不是脚本自带的。`跑GEE.js` 的职责就是把这几样注入进去再执行你的脚本
> （详见第三节）。
>
> **一切 GEE 脚本都要通过 `跑GEE.js` 跑**，示例也不例外。
> 直接跑会得到一段中文提示告诉你该怎么办，不会只甩一个英文报错。


```bat
:: 跑一个脚本
node 测试台\跑GEE.js "我的脚本.js"

:: 跑整个目录（只跑目录里的 .js，不递归子目录）
node 测试台\跑GEE.js --all "某个目录"

:: 重的脚本放宽超时（默认 300 秒；大区域长时序常要 900~1200）
node 测试台\跑GEE.js --timeout 1200 "很重的脚本.js"
```

★ **你交给它的每个 `.js` 都会真跑**，它不会自作主张跳过任何文件。
要排除某个文件，别把它放进 `--all` 的目录里就是了。

**先看效果就双击 `跑一个试试.bat`**，它会依次跑两个示例：一个正常的、一个故意写错的。

## 输出怎么读

```
▶ LandTrendr森林扰动监测.js
      print: ① 年度时序影像数：  24                  ← 脚本里 print 的真实结果
      addLayer: ③ 扰动年份 波段 ["yod"]              ← 这层算得出来，波段名是 yod
      Export.image: disturbance_year （已跳过实际导出）

   ── 小结 ──  耗时 22.4s　print 7　图层 3　导出 0
   ✓ 跑通，无报错无告警
```

出错长这样（会把可用波段名一并列出来，很好用）：

```
      print: ④ 显著趋势：  【服务端报错】Image.select: Band pattern 'p-value' did not match
                            any bands. Available bands: [t_tau, t_p-value, NBR_tau, NBR_p-value]
```

★ **报错的行号往往不是有 bug 的行**——原因见下面第三节"惰性计算"。

## 它能查出什么 / 查不出什么

**能查**（只有真连服务器才暴露，静态审读一律看不出来）：

- 波段名写错（`B08` vs `B8`、`ST_B6` vs `ST_B10`、`p-value` vs `NBR_p-value`）
- 归约器输入个数不对（`sensSlope` 要 2 个波段、`kendallsCorrelation()` vs `(2)`）
- 数组维度不匹配（二维数组上 `arrayGet` 只给一个波段的下标）
- 集合不同构（同一波段在不同影像上取值范围不同）
- 过滤条件匹配不到（GAUL 里云南叫 `Yunnan Sheng`，不是 `Yunnan`）
- 内存与体积超限（`User memory limit exceeded` / `Computed image is too large`）
- 稀疏数据抽样抽空（GEDI 给 `numPixels` 只命中 8 个点）

**查不出**：

- Export 的实际产物（跳过了导出，只校验参数）
- 视觉效果（配色、图例、拉伸合不合适）
- 结论对不对（**能跑通 ≠ 方法站得住**）
- 交互式与批处理的额度差异（有些计算交互式跑不动、必须走 Export，只能人判断）

所以第一次上机仍要留调试时间，但性质变了：
从"代码可能根本跑不起来"变成"参数可能要调"。

## 安全边界

- `Export.*` **只校验参数、不真导出**——不烧配额，不往你的 Drive / Asset 写任何东西。
- 脚本在 `vm` 沙箱里执行，不给 `require` / `process`，碰不到宿主机。
- 只读地跑，不改服务端任何数据。

# 三、内部怎么跑的（简版）

> ### 🡒 完整原理见同目录的 **《原理.txt》**
> 那一份讲透了"实际发生的事、本地跑起来的三个必要条件、以及为什么这件事以前一直没做成"，
> **换台电脑排错、或者把这套东西交给别人接手时先看它**。
> 本节只留日常用得上的几条，不重复展开。
>
> 全文的实例都来自真实调试记录，为便于阅读把脚本名简写成
> 「森林扰动脚本」「生物量脚本」「分县统计脚本」之类。

## 3.1 一句话：算力全程在 Google 那边

客户端库 `@google/earthengine` **不做任何计算**，只把脚本里的 JS 调用拼成一段 JSON
（一张"计算图"）POST 给 Google 的 REST 接口，服务端算完返回 JSON。
本地全程只干三件事：**拼 JSON、发 HTTP、解析 JSON**。

所以"本地能不能跑 GEE"这个问题，等价于
"**这个 POST 发不发得出去，手上有没有有效的 token**"——与本机性能无关。

本地跑起来只有三个必要条件：**能拼那棵树**（npm 包就是干这个的）、**有 token**
（refresh_token 换 access_token）、**那个 POST 出得去**（换掉 HTTP 出口）。
三条齐了就通了；界面外壳只是让脚本别在那几行上崩，与能不能算无关。

## 3.2 必须先懂：GEE 是惰性计算

在 Code Editor 里写：

```js
var ndvi = img.normalizedDifference(['B8', 'B4']);
```

**服务器什么都没算。** 客户端只是在内存里攒了一棵"计算描述树"：
"拿这景影像 → 取 B8 与 B4 → 做归一化差值"。

只有当你 `print()`、`Map.addLayer()`、`Export` 时，这棵树才被序列化成 JSON
发去服务端，真正开始算。

**三个推论，全都很要紧：**

1. **语法检查毫无用处**。波段名写错、集合是空的、归约器参数个数不对——
   攒树阶段一律不报错，`node --check` 全过。
2. **必须有东西去"触发"计算**，否则脚本跑完什么也没发生。
   测试台就是靠 `print` 触发的——它把 `print(x)` 实现成**真的调 `x.getInfo()`**，
   这是整台机器唯一的发动机。
3. **报错的行号往往不是有 bug 的行**。错误统一在 `print`/`addLayer` 那一刻爆出来。
   森林扰动脚本那次，报错的 `print` 在第 250 行，真正的 bug 在第 141 行。

## 3.3 Code Editor 拆开来看是两层

| 层 | 是什么 | 本地拿不拿得到 |
|---|---|---|
| **计算层** | `ee.Image`、`ee.Reducer`、`ee.Algorithms`、`ee.Geometry`… | ✅ npm 包 `@google/earthengine`，**Google 官方发布，就是同一套 JS API** |
| **界面层** | `print`、`Map`、`Export`、`ui`、`Chart` | ❌ 只存在于编辑器那个网页里 |

所以缺的**不是计算能力，是那层外壳**。补上外壳就能跑。
界面层的四样东西**没有一样参与计算**，因此本地把它们做成假的不影响测试有效性
（为什么，见《原理.txt》第二节）。

## 3.4 逐步流程

### 第 0 步　选一条能通 Google 的路

按《原理.txt》3.5 那张表的四级顺序定下代理，`apply()` 写进环境变量，终端打印一行「联网方式：…」。
四级全不通时先警告"下面多半会失败，先双击 `环境自检.bat`"，
而不是让人对着一堆 `ETIMEDOUT` 猜。

### 第 1 步　取令牌

读 `%USERPROFILE%\.config\earthengine\credentials`，里面有个 `refresh_token`
（`earthengine authenticate` 那次留下的，长期有效）。

拿它去 `https://oauth2.googleapis.com/token` 换一小时有效的 `access_token`：

```
POST oauth2.googleapis.com/token
  client_id=<earthengine 命令行工具自带的公开 client>
  client_secret=<同上>
  refresh_token=<凭据文件里的>
  grant_type=refresh_token
```

★ `client_id` / `client_secret` **不要自己猜**，从已装的 Python 包里读真值：

```bat
py -3.12 -c "import ee.oauth as O; print(O.CLIENT_ID); print(O.CLIENT_SECRET)"
```

（我第一次照着截断的输出猜，直接 `invalid_client`。）

### 第 2 步　初始化

```js
ee.data.setAuthToken('', 'Bearer', token, expiresIn, [], function () {
  ee.data.setProject(PROJECT);          // PROJECT 来自 配置.txt
  ee.initialize(null, null, onSuccess, onError, null, PROJECT);
}, false);
```

**项目 ID 是必须的**，现在的 GEE 不允许无项目初始化。它读的是本目录 `配置.txt`
里的「项目ID = 」那一行（也可用环境变量 `EE_PROJECT` 临时覆盖）。
初始化时客户端会去拉一份"算法清单"（`/v1/projects/<项目>/algorithms`），
这一步也是第一个会暴露网络问题的地方。

### 第 3 步　造外壳

`print` 是整台机器的发动机：

```js
const shimPrint = function () {
  for (const a of arguments) {
    if (a && typeof a.getInfo === 'function') {
      try   { parts.push(a.getInfo()); }        // ← 真去服务器算
      catch (e) { R.err.push(e.message); }      // ← 服务端报错抓在这
    } else {
      parts.push(a);                            // 普通字符串直接打印
    }
  }
};
```

`Map.addLayer(x, vis, name)` 不画图，但对 `x` 取一次 `bandNames()`——
**验证这一层算不算得出来**；若返回空数组就告警"零波段影像"
（这正是"空集合取 median()"的病征）。

`Export.*` **只校验参数并打印，不真导出**。顺便检查 `region`、`scale`、`maxPixels` 齐不齐。

`ui.*` 全部返回一个 Proxy 空部件，**任何方法都返回自身**，保证
`ui.Chart.image.series(...).setOptions(...).setChartType(...)` 这种长链不断。

### 第 4 步　在沙箱里执行

```js
vm.runInNewContext(src, vm.createContext({
  ee, console, print, Map, Export, ui,
  Math, JSON, Date, Number, String, Array, Object, ...
  require: undefined, process: undefined, module: undefined,   // 不给脚本碰宿主
}), { filename: name, timeout: timeoutSec * 1000 });
```

**脚本一个字不改**，从磁盘读进来直接跑。

### 第 5 步　收结果

每个脚本报：耗时、print 数、图层数、导出数、服务端报错清单、告警清单。
整批跑完出一张总表。

## 3.5 查错的正确姿势

因为惰性计算，报错位置≠出错位置。所以流程是：

**① 看到报错 → ② 写一个最小复现脚本，把中间步骤一层层 print 出来 → ③ 看哪一步开始挂。**

森林扰动脚本那次的实际过程：

```
步骤A  mag 在样窗的均值            ✓ 0.0116
步骤B  裁剪后像元数                ✓ 2095
步骤C  connectedPixelCount 均值    ✗ Computed image is too large      ← 就是它
步骤D  reduceToVectors 图斑数      ✗（被 C 带崩）
```

一眼定位到 C。把 `connectedPixelCount(256)` 改成 `(32)` 后，C 和 D 都通了，
顺带耗时从 161 秒降到 35 秒。

## 3.6 能连服务器之后，可以直接"问"而不是"猜"

这是最大的收益。不用查文档、不用猜，写个探针跑一下就有答案：

```js
print('A) 双波段 kendallsCorrelation()  ：', 集合.reduce(ee.Reducer.kendallsCorrelation()).bandNames());
print('C) 双波段 kendallsCorrelation(2) ：', 集合.reduce(ee.Reducer.kendallsCorrelation(2)).bandNames());
```

实测输出：

```
A) ["t_tau","t_p-value","NBR_tau","NBR_p-value"]      ← 原来七处代码都这么写，所以 select('p-value') 全挂
C) ["tau","p-value"]                                   ← 该用这个
```

同样方法测出来的还有：

- GAUL 里云南到底叫什么 → `aggregate_array('ADM1_NAME')` → `Yunnan Sheng`（不是 `Yunnan`）
- 普洱叫什么 → `Pu'er`（**带英文撇号**）
- GEDI 哪一年光斑多 → 逐年 `reduceRegion(count)` → 2022 年最多（46520）
- `numPixels` 给不给差多少 → 给 4000 → **8 个点**；不给 → **6390 个点**

**结论：凡是"我记得应该是……"的地方，写三行探针测一下，比查文档快也比记忆可靠。**

# 四、换一台电脑怎么装

## 4.0 最省事的办法：双击两个 bat

把**整个 `测试台\` 文件夹**拷到新电脑（U 盘、网盘都行），然后：

1. 双击 **`安装.bat`** —— 检查 Node、装依赖、跑自检，一条龙
2. 若自检提示项目 ID 不对，打开 **`配置.txt`** 改一行，再双击 **`环境自检.bat`**

自检会**逐项告诉你缺什么、怎么补**，不用回来翻这份文档。全部 [通过] 就能用了。

> **实在搞不定**：把自检的完整输出复制下来，连同这份《说明.md》与《原理.txt》
> 一起丢给 AI 助手，它有足够信息判断。这也是这两份文档写这么细的原因。

## 4.1 前提

| 需要 | 怎么确认 | 没有怎么办 |
|---|---|---|
| **Node.js 20.19 以上** | `node -v` | 到 https://nodejs.org/ 装 22 LTS 或更高 |
| 一个 GEE 账号 + 已注册的 Cloud 项目 | 见 4.3 | 到 code.earthengine.google.com 注册（学术免费） |
| 已认证过的凭据 | 见 4.4 | `earthengine authenticate` 跑一次 |
| 能访问 Google（可能要代理） | 见 4.5 | 多数情况下不用管，工具会自动找 |

★ **为什么是 20.19 不是 16**：依赖 `https-proxy-agent@9` 是纯 ESM 包
（`"type": "module"`，`engines` 声明 `>=20`），而本项目用 CommonJS 的 `require()` 加载它。
`require(ESM)` 要 **Node ≥ 20.19 或 ≥ 22.12** 才默认放开，否则报 `ERR_REQUIRE_ESM`。
装了 Node 18 LTS 会跑不起来，而且报错信息很容易被误读成"包没装"。

**不需要装 Python。**

## 4.2 装依赖

`安装.bat` 会自动做。手动的话，在本目录：

```bat
npm install
```

装两个包：`@google/earthengine`（官方 JS 客户端）、`https-proxy-agent`（走代理用），
约 111 MB。

★ **两种搬运方式的区别**：

| 方式 | 结果 |
|---|---|
| **整个文件夹拷贝**（U 盘/网盘） | `node_modules\` 一起过去，连 `npm install` 都省了，离线可用 |
| **从 git 克隆** | 只有源码（`node_modules/` 被 `.gitignore` 排除），**必须联网跑一次 `npm install`** |

## 4.3 项目 ID —— 只改 `配置.txt` 这一个地方

打开本目录的 **`配置.txt`**（记事本即可），把这一行换成你自己的：


★ 没改的话不会悄悄回落到别人的项目：占位符会被单独识别出来，
自检第 4 项直接报「你还没填自己的」。

## 4.5 代理 —— 通常什么都不用做

工具**自己会找**一条能通 Google 的路，四级顺序（详见《原理.txt》3.5）：

```
① 配置.txt 里的「代理 = …」  →  ② 环境变量 HTTPS_PROXY / HTTP_PROXY
                             →  ③ 直连  →  ④ 扫本机常见代理端口
```

每一级都要**真的连一次 Google** 才采信，所以不会选中一个"端口开着但用不了"的代理。
终端会打印一行「联网方式：…」告诉你这次走的是哪条。

**只有两种情况需要你动手**：代理端口不在常见清单里（10808/10809/7890/7897/1080/8080/8888/2080/10000），
或者不想每次都花几秒探测。这时打开 `配置.txt`，把这一行前面的 `#` 去掉并改成你的端口：

```
代理 = http://127.0.0.1:10808
```

也可以设环境变量（等价于第 ② 级）：

```bat
set HTTPS_PROXY=http://127.0.0.1:10808
```

★ 但**不要只依赖环境变量**：双击 `.bat` 打开的是全新 cmd 窗口，不继承你在别处 `set` 的值。
要固定下来就写进 `配置.txt`，或加进系统环境变量。

# 五、踩过的坑（每个都真花了时间，别删）

## 坑 1　Node 不读 HTTPS_PROXY

**现象**：Python 的 urllib 明明能连通 Google，Node 一律 `ETIMEDOUT` / `ECONNRESET`。

**原因**：Python 的 urllib 会自动读 `HTTP_PROXY`/`HTTPS_PROXY` 环境变量，
**Node 的 `http`/`https` 模块完全不读**，必须显式给 agent。

**解法**（**注意：已不是当初那一版**）。最初的做法是把 `HttpsProxyAgent` 装到
`https.globalAgent`，但那条路被坑 2 证明走不通，现在的代码里**已经没有 globalAgent 补丁**。
现行做法是：启动时先由 `代理探测.js` 定下代理并写进 `process.env`，
之后**每个要发请求的地方各自现建 agent**（换令牌、异步 XHR、子进程各一处）。
没有代理的机器上 agent 为 `undefined`，等同直连。

★ 由此带出一条通用规矩：**代理地址一律现读 `process.env`，不要在模块加载时读死**。
因为探测发生在模块加载之后，读死的话探测结果对已加载的模块完全无效
（症状：自检说探到了代理，请求还是超时）。

## 坑 2　EE 客户端不认 globalAgent（最难的一个）

**现象**：坑 1 修完，`oauth2.googleapis.com` 能连了，但 EE 初始化仍报
`Server returned HTTP code: -1 for GET .../algorithms`。

**原因**：`@google/earthengine` 在 Node 里用的是 npm 包 `xmlhttprequest`。那个包
① 不读代理环境变量，② **同步请求是另起子进程做的**——
所以给 `https.globalAgent` 打补丁对它**完全无效**（实测 status 恒为 0）。

而 EE 的 `getInfo()` 走的正是同步路径。

**解法**：自己实现一个走代理的 `XMLHttpRequest`（`xhr代理.js`）：
异步用 `https.request` + 代理 agent；同步用 `spawnSync` 起子进程发请求。

**光设 `global.XMLHttpRequest` 还不够**——`@google/earthengine` 的
`build\main.js` 第 2 行是
`const XMLHttpRequest = require('xmlhttprequest').XMLHttpRequest;`，
它自己会覆盖回去。所以要**拦截模块加载**：

```js
const Module = require('module');
const _load = Module._load;
Module._load = function (request, parent, isMain) {
  if (request === 'xmlhttprequest') return { XMLHttpRequest: ProxyXHR };
  return _load.apply(this, arguments);
};
```

这样不用改 `node_modules`，`npm install` 重装也不会丢。

## 坑 3　client_id 不能猜

**现象**：`{"error": "invalid_client", "error_description": "The OAuth client was not found."}`

**原因**：我照着一段被截断的终端输出把 client_id 补全了，补错了。

**解法**：从已装的 Python 包里读真值（见 3.4 第 1 步）。

## 坑 4　长任务被代理掐断，伪装成代码错

**现象**：跑了 300—600 秒后报
`Failed to contact Earth Engine servers. Please check your connection, firewall...`
——看着像代码错，其实是网络层被掐了。

**解法**：`xhr代理.js` 对**网络层失败**（status 0 / 502 / 503 / 504）重试 3 次，
每次退避 3/6 秒；服务端返回的业务错误（带 JSON 的 4xx/5xx）**不重试**——那才是要抓的真问题。

★ 重试也救不回来时，多半**真的是计算太重**。分县统计脚本那次就是：
它自己在配置里写着"统计量用粗尺度估计"，代码里却用了 30 m 成图尺度，
在 4.4 万 km² 市域上 10 个县逐个归约，596 秒超时；改用粗的 `statScale` 后 433 秒跑通。

## 坑 5　ui.* 的链式调用会断

**现象**：`ui.Chart.image.series(...).setOptions is not a function`，脚本从中间断掉。

**原因**：我一开始把 `ui.*` 的部件写成普通对象，只实现了几个方法。
但 Code Editor 的 Chart 是长链：`.series().setOptions().setChartType()...`

**解法**：用 `Proxy`，**任何属性访问都返回一个返回自身的函数**，链条永远不断。

## 坑 6　"自动跳过某类脚本"这个功能本身就是个坑（已移除）

**背景**：早期版本会按文件名和正文关键词，自动跳过一类"填空骨架"脚本
（含 `/* 补全 */` 占位、`TODO-N`、抬头写着"学生版"的），
理由是它们本来就不完整，跑出"跑通"或"报错"都是误导。

**为什么撤掉**：这个判据对**别人的脚本**是灾难。
任何人的正常脚本里出现一句 `// TODO-1 换成研究区` ——
整个文件就被静默跳过，终端只多一行不起眼的 `⏭ 跳过`，
总表里那一格是空的，看起来像"没问题"。

**静默跳过比跑错更难查**：跑错至少有报错可循，跳过是彻底的无声。

★ 教训写在这里，比结论本身更值钱：
**校验工具绝不能自作主张决定"哪些不用校验"。**
要排除什么，应该由调用方在**入参**上表达（别把它放进 `--all` 的目录），
而不是由工具去猜正文内容。

现在的行为：**你交给它的每个 `.js` 都会真跑**，一个不漏。

## 坑 7　.bat 必须存成 GBK + CRLF，否则中文全是乱码

**现象**：双击 `跑一个试试.bat`，窗口里中文全是乱码。

**原因**：我按习惯存成了 **UTF-8 + LF**。Windows 的 cmd 解析批处理时按
**系统 ANSI 代码页**（简体中文机器是 cp936/GBK）逐行读，读到 UTF-8 字节就花了。
开头加 `chcp 65001` 也救不回来——那一行本身还没生效时，后面几行已经被按 GBK 解过了。

**当时的解法**：存成 **GBK + CRLF**，不要加 `chcp`。这在"双击运行"这一种用法下是对的。

---

### ★ 2026-08-18 修正：这条结论**不完整，而且埋了一个更深的雷**

GBK 方案只在 **cp936 控制台**（Explorer 双击）下成立。从 UTF-8 终端调用同一个
`.bat`，GBK 字节被当成 UTF-8 读，**中文文件名直接解坏**：

```
Error: Cannot find module 'C:\...\测试台\??GEE.js'
```

`跑一个试试.bat` / `环境自检.bat` / `安装.bat` 三个都中招——它们里面原本都写着
`node 跑GEE.js` 这种**中文文件名**。乱码只是难看，这个是**直接崩**。

而且不只是文件名：**参数里的中文路径**（`"示例\演示_....js"`）一样会被啃掉。

**完整的解法（三条一起才成立）**：

1. **`.bat` 内容全 ASCII** —— 文件名、参数一律不出现中文。
   文件名本身可以是中文（`%~dp0` 是 cmd 运行时从真实路径展开的，不来自 .bat 字节）。
2. **开头加 `chcp 65001 >nul`** —— 纯 ASCII 的 .bat 没有"自身被解错"的问题，
   所以 chcp 完全有效（这正是当年那句"加 chcp 也救不回来"不成立的前提）。
3. **所有中文交给 Node 输出** —— Node 永远按 UTF-8 读源码、写 stdout，
   配合上一条，任何代码页下都正常。

本目录的 `run.js` 就是为此存在的 **ASCII 入口壳**：

```bat
node run.js check          → 环境自检.js
node run.js demo           → 依次跑 示例\ 下两个演示脚本
node run.js bench <参数>    → 跑GEE.js <参数>
```

中文文件名和中文路径全部收在 `run.js` 里（`.js` 由 Node 按 UTF-8 读，与代码页无关）。

> `安装.bat` 例外：它有大段中文排错指引，仍存 GBK。
> 但它的**功能性调用已经 ASCII 化**（`node run.js check`），所以不会再崩；
> 从 UTF-8 终端调用时只是那些提示文字显示成乱码，不影响执行。

**核对办法**：直接数高位字节，比肉眼看可靠得多——

```powershell
Get-ChildItem *.bat | ForEach-Object {
  $b = [System.IO.File]::ReadAllBytes($_.FullName)
  "{0,-18} 高位字节 {1}" -f $_.Name, ($b | Where-Object { $_ -gt 127 }).Count
}
```

纯 ASCII 的应该是 `0`。**两个代码页都要实跑一遍**（`chcp 936` 和 `chcp 65001`），
只测一个就是当年漏掉这个雷的原因。

## 坑 8　robocopy 才搬得动这个文件夹

**现象**：`mv` 和 `Move-Item` 都报 `Permission denied` / `Access denied`。

**原因**：`node_modules` 里层级很深、路径很长。

**解法**：`robocopy 源 目标 /E /MOVE`。退出码 0—7 都算成功（不是 0 才成功）。
