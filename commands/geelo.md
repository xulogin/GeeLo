调用 geelo skill（`geelo:geelo`），严格按它的规矩执行。

用户输入：$ARGUMENTS

---

## 没有输入内容时 → 跑环境自检，报告状态

```bash
node "<GeeLo>/测试台/环境自检.js"
```

然后**用大白话**告诉用户现在能不能干活：

- **全部通过** → 「环境正常，可以开工。直接跟我说你想算什么就行。」
- **只缺依赖** → 自己在 `<GeeLo>/测试台` 跑 `npm install`，装完重跑自检再报
- **缺凭据或项目 ID** → 跑 `node "<GeeLo>/测试台/认证.js"`，它自动开浏览器；
  告诉用户「点一下『允许』就行」。凭据和项目 ID 它都会自动配好，不用装 Python。
  **不要让他把凭据内容贴给你。**

别把自检的原始输出整段糊给用户，挑出他要做的事说。

---

## 有输入内容时 → 那就是需求，直接开工

按 skill 里的铁律做，重点是这三条：

1. **写完必须实跑验证**：`node "<GeeLo>/测试台/跑GEE.js" --timeout 900 "<脚本>"`
   没跑过的脚本不算交付。
2. **跑通不等于对**：跑完再看一层数值——量级对吗、符号对吗、讲得通吗。
3. **先小后大**：Debug 阶段先拿一小块区域、一个时间段试，通了再放大。省用户的配额。

成果脚本写到**当前工作目录**，探针和临时脚本写到临时目录。

交付时附上实跑输出当证据。跑不通就说跑不通。
